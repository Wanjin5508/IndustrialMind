## 完成剩余门槛

1. 根目录 `.env.local` 配置 `OPENAI_API_KEY`、`OPENAI_MODEL`；必要时配置兼容 Responses API 的 `OPENAI_BASE_URL`。不要在聊天或提交中填写密钥。
2. 重启 API。运行 `python scripts/live_acceptance.py`，它只发送 DEV-001 合成文本和 PDF 页图，不自动审批。
3. 在工作台核对真实输出、模型名、响应 ID、usage、耗时；若有页级视觉待确认项，工程师逐项复核，补充依据。

## 已知边界

- 当前只有一个零件模板；孔数量、位置及完整几何由审批人显式确认，不宣称 CAD 理解或制造可行性认证。
- PDF 文本行可回查，图像定位为页级；不能宣称已完成 M3 区域定位与稳健性。
- 本地演示角色令牌公开，不是 SSO。SQLite 与文件目录必须由本机访问权限保护。
- 中途终止模型请求可能留下 EXTRACTING；自动恢复/任务租约留待 M6。重试使用新任务并保留旧记录。
- 文件解析失败可能留下孤立上传文件；仅在停止服务并备份后人工整理 `var/uploads`。上传上限是应用读取限制，生产环境还需网关限制。
- 模型 provider 已与 DeepSeek Responses 实测通过；其他服务仍需独立验证。M2 未配价格表，费用留空。
- API 支持自定义演示令牌；当前 UI 角色切换使用默认令牌，自定义令牌时可通过 API 操作。
- 不含企业连接器、冻结评测、生产部署与正式客户报价，M3–M9 继续遵循原 roadmap。
