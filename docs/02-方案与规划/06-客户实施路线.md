# PrecisionMotion 客户实施路线

从德国工厂的标准件与可控变型件起步。客户各工厂的源系统、流程负责人和授权范围在第一阶段确认。以下月份从客户立项开始计，与原型开发里程碑分开。[[docs/01-原始说明/01-设计挑战]] · [[docs/04-项目介绍与展示/11-方案答卷]]

| 阶段 | 工作与交付 | 牵头人与进入下一阶段的条件 |
|---|---|---|
| 0–3 个月 · 德国单产品族试点 | 测现行工时和周期，整理批准的零件版本、材料、工艺和费率。用历史任务做配对回测，再对连续进件做影子运行。工程师复核每单结果，报价负责人记录是否可采用。 | 工程经理与报价负责人共同验收。关键漏阻断为零，配对工时差和适用率能支撑更新后的商业模型，IT 审查通过。 |
| 3–9 个月 · 部门推广 | 在德国扩到有批准模板的产品族，接企业身份、项目权限与审批流。先只读获取 PLM/ERP 数据，核对字段和版本。对账通过后开启受控 ERP 草案写入。建立知识发布、指标巡检、问题反馈与回滚流程。 | 工程运营、PLM/ERP 管理员和财务共同验收。对账及重放不产生重复草案，过期输入能阻断，权限分离经过验证，采用率及维护成本支持继续扩张。 |
| 9–24 个月 · 多工厂平台 | 逐厂接入波兰和中国，分别确认权限、数据处理要求、单位、费率和工序。新场景按业务优先级试点，包括原生 CAD、装配 EBOM/MBOM、工艺规划、变更传播及 MES 质量反馈。 | 各厂工程、质量与 IT 共同批准。每个新增场景有本地标注集、独立成效指标、故障演练、运维责任人和投资测算。 |

## 第一阶段怎么测

1. 工程经理先定义适用条件，连续记录进件类型、资料缺失、模板是否覆盖和退回原因。初步目标是至少收集 30 对可比任务，并另备已知版次冲突、材料缺失、过期费率和权限例。目标样本量随进件与异常发生率调整。
2. 按复杂度和图纸类型分层，比较现行流程和辅助流程，轮换工程师及先后顺序，减少熟悉同一图纸带来的偏差。异常任务、转人工及返工也纳入统计。质检或资深工程师独立核对关键字段、版次、依据和结果。
3. 每单记录收件、开始作业、暂停及恢复、进入审核、提交修正、内部批准等事件。分别统计主动工时和等待，报告分母、样本缺口、配对差值分布与报价周期变化。记录漏阻断和误阻断的业务影响。
4. 用实测的适用率、工时差和实际成本复算三年 ROI。若出现关键漏阻断或越权，先暂停推广并用新冻结样本复验。若经济性不足，先查复核或等待瓶颈，再决定是否调整范围。[[docs/02-方案与规划/05-商业论证]]

## 权威来源与写入边界

| 责任面 | 初期读取与验证 | 推广后的控制 |
|---|---|---|
| PLM 与工程变更 | 工程数据负责人提供零件号、发布版次、生效状态、替代关系及批准图纸。版本不明确进入工程澄清。 | 将变更事件映射到受影响任务，按文件摘要、版次和有效性复核；需要重新核准的草案回到审批前。 |
| ERP 与费率 | 成本工程维护材料目录、币种、工厂费率、生效期和工艺成本依据。并行复算并与人工样本对账。 | 批准快照映射成内部草案；按任务、版本和目标系统生成幂等键，记录回执、对账差异和人工重试。 |
| MES 与工艺 | 工艺负责人选择已执行工单，核对计划和实际工时、工序及缺失值。 | 将工时偏差提供给规则维护人审核，批准后更新工艺版本。跨工厂按各自设备和适用范围校准。 |
| 账号、文档与日志 | IT 核定项目、工厂、角色和模型可访问资料，配置留存及审计责任。 | 接企业身份和对象权限，保留角色、输入、参考、模型与批准版本。定期重验跨项目隔离和撤权。 |

发生模型或源系统故障时保留任务、证据和来源快照，交回工程队列。关闭故障连接器或回退参考版本后先对账，再恢复处理。首轮功能与模拟集成的验收证据见 [[docs/03-实施与开发/09-阶段验收/06-M6恢复与集成]] 和 [[docs/03-实施与开发/09-阶段验收/09-M7独立评测]]。
