# 常见问答

| 面试官可能问 | 建议回答 | 当前证据或限制 |
|---|---|---|
| 这只是一个模型包装器吗？ | 展示证据校验、权限过滤、Decimal、版本审批与审计；这些机制独立于模型 | 模型只在抽取 Provider 中 |
| 为什么先做这么小的范围？ | 单产品族能建立可复核真值、适用模板和异常边界，便于试点验证 | 不承诺任意图纸通用 |
| 换模型需要重写系统吗？ | 保持 Extraction 与来源契约，替换 Provider 并重新评测供应商能力 | 当前真实验证的是配置的 DeepSeek 服务 |
| 识别错了怎么办？ | 不支持的来源阻断；图像事实人工复核；修正保留原值并使旧结果失效 | 模型可能给出看似匹配但语义错误的事实，仍需工程复核 |
| 准确率是多少？ | 12 个独立合成包上，DeepSeek 读对 153/153 个可见字段，3/3 缺失项保持为空；其中 8 项是需人工确认的扫描页证据 | 尚无客户图纸准确率；12 个料号使用标准字段标签 |
| 为什么用 SQLite？ | 当前是单机演示，能验证事务与版本锁；多用户试点再按需求迁移数据库 | 没有分布式一致性或高可用承诺 |
| 如何接 ERP/PLM？ | 先确认权威版次、身份和费率来源，先只读/影子运行，再通过审批绑定写入适配器 | 这些连接器尚未实现 |
| 59.7% 的 ROI 从哪来？ | 说明适用率、采用率、每单净节省、兑现比例和成本。基准每单节省 45 分钟，按当前假设约 28.2 分钟持平 | 三档都是产能价值情景。试点采工时、周期和采购成本后重算 |
| 文档里的恶意指令怎么办？ | 展示诱导样例中系统仍按原文 48 件和批准费率计价，且不能代替审批人 | 已验证一个文档诱导变体；复杂攻击仍需扩样 |
| 如何保护客户数据？ | 本地 key、服务端权限、禁止真值进运行时；试点前确认是否能外发图纸及保留策略 | 当前演示令牌不是生产身份；没有完成客户安全审查 |
| 为什么不做自动报价？ | 采购、产能、交期和合同信息未验证；当前只允许批准内部预算 | 输出明确 INTERNAL BUDGET DRAFT |
| 你自己的工程贡献是什么？ | 解释范围选择、数据构造、证据模型、状态/审批规则、测试和取舍；如实说明 AI 辅助编码 | 不把工具生成内容说成独立手工完成 |
