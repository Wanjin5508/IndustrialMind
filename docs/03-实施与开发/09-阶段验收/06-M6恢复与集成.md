# M6 可靠性与集成预览验收

Owner: Engineering · Status: Passed (development scope) · Updated: 2026-11-10

| 路线图门槛 | 验收结果 |
|---|---|
| 有界重试和故障定位 | 注入三次模型超时，前两次可重试，第三次进入 `FAILED_FINAL`。重启保留次数，第四次请求返回 `RETRY_LIMIT`。切换回放继续原任务。 |
| 执行中断恢复 | 模拟旧执行器挂起，使用同一 SQLite 启动新应用。期限内禁止回收，超期后工程师可恢复。旧执行器迟到的结果收到 `VERSION_CONFLICT`。 |
| 输入输出版本日志 | 识别与计价审计包含输入版本、输出版本和指纹。失败事件包含尝试次数、故障码与结果版本。 |
| 回放来源 | DEV-001 使用 M3 保存的 `deepseek-flash` 输出。文件 SHA-256 一致才允许回放，并把来源定位映射至当前任务。页面、审计和导出草案均标记 `REPLAY`。DEV-002 回放请求被拒绝。 |
| 模拟集成和权限 | PLM 显示发布版次 B，DEV-003 可对照图纸 A。ERP 显示当前有效草案，过期草案不返回载荷。MES 显示样例工时。未认证请求和越权访问被拒绝。 |
| 审批与导出 | 已批准任务的继续处理保留审批。重复提交旧版本返回 409，按最新版本重复导出返回原文件和原事件。 |

在隔离库 `var/m6-browser` 完成浏览器验收。DEV-001 经三次模拟超时后切换回放，计算 EUR 2,547.00，加载 PLM、ERP、MES 三项模拟数据，再切换审批人完成批准与导出。MES 工时为 B 版铣钻计划 7.2 分钟/件、样例 8.1 分钟/件。

验证包括 `tests/test_m6.py` 的六项场景、101 项累计后端测试、Ruff、前端生产构建和浏览器操作。模型超时使用本地注入，回放使用已有记录。真实抽取的验收见 [[docs/03-实施与开发/09-阶段验收/03-M3证据校验]]。

M6 采用人工触发重试和超期恢复。租约默认是 `4 × 模型超时 + 30 秒`，用于判定能否回收，无法取消外部服务已收到的请求。每个任务按当前资料 SHA-256 和识别方式分别计数，成功后清除该方式的连续失败计数。认证等永久失败直接停止。模拟适配器仅支持 PM-DEMO / DE-DEMO / PM-BRKT-010，MES 样例不参与报价计算。
