# M7 前置修复验收

基于 [M6 需求覆盖审计](m6-requirements-gap-analysis.md)，修复 G01 和 G02，交付 G04 的单件毛坯草案，并确定 G03 的评测范围。

| 项目 | 行为与验证 |
|---|---|
| G01 版次冲突 | RFQ 要求版次和图纸版次都以原文件为准。只改字段返回 `409 REVISION_OVERRIDE`；换 B 版后可重新识别和计价。原读值相同且有页图依据的人工确认仍受支持。以旧逻辑保存且指纹一致的错误批准也无法下载或进入 ERP 预览。 |
| G02 下载闸门 | 审批人从独立下载接口取 Markdown 或 JSON。普通任务响应只带文件名。审批快照、原件版次、任务版本和当前参考数据均需匹配。费率或毛坯模板变化后拒绝下载。下载不重复生成文件。 |
| G04 单件毛坯 | 受控模板 `bracket-routing-demo-2` 输出一行 Al-6061-T6 毛坯，规格 `82 × 52 × 13 mm`，每成品件需一件。成本页、Markdown 和 JSON 显示批次用量和模板、目录版本。100/500 件报价仍为 €2,547.00 / €12,255.00。 |
| G03 冻结口径 | 抽取/证据与端到端报价分开计分。报价正例按案例使用隔离的批准参考和独立复算答案。正式冻结数据与评分属于 M7。 |

后端回归 **106 项通过**。在隔离库 `var/pre-m7-browser` 的浏览器复核中，成本页显示毛坯规格、每件与批次用量，审批人能生成文件。调整隔离费率后，旧页面的 Markdown 请求及刷新后的 JSON 请求均返回 409，并提示重新计价和审批。

原型已有报价的参考指纹随规则和模板升级而变化。需要继续交付时，重新计价、审批并生成新版文件。历史已保存到客户端的副本通过其原版本标识管理。
