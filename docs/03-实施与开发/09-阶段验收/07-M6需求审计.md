# M6 需求覆盖与缺口分析

审计基线 `8bb2fb3`，分支 `codex/m6-reliability-integration`。实现基线 `6ecfce5`。范围为 PrecisionMotion 的 Option B 原型、Part 1–5 方案要求及项目自定验收。评估按业务结果、规则、输出和验证证据进行。

下文保留审计时的状态。G01–G04 的后续修复及验收见 [[docs/03-实施与开发/09-阶段验收/08-M7前置修复|M7 前置修复验收]]。

## 1. 结论与进入 M7 的判断

**题目 Option B 的原型最低要求已满足。** 已有可运行的 RFQ 报价链路，能展示真实多模态识别、证据回查、受控计价、人工审批及内部草案导出。审图、知识查询、模拟集成和回放提供了可演示的补充。架构取舍与样例输入输出都有文档和验收记录。题目只要求原型演示一项或多项能力，完整装配 BOM、真实 ERP 写入和企业部署不构成原型缺项。

**自定 MVP 尚有缺口，M7 的正式评测条件未就绪。** 两项控制问题已复现：原图 A 版可在无新证据时改成 B 版进入批准流程，费率变更后的旧导出仍能从任务详情下载。另有两个需要明确决定的范围问题：早期 P0 承诺独立物料草案，而系统只产出材料成本行；M7 要求独立零件且包含正常闭环，而默认计价模板只接受一个料号和一组尺寸。可以先开展独立样本设计与标注，正式冻结、跑分和宣称验收前应关闭前两项控制问题，并确定后两项的验收口径。

**Part 1–5 已有方案底稿，最终交付包仍不完整。** 三档 ROI 和三阶段客户路线已有推导，缺的是测量结果、可交给评审者的统一说明以及干净环境复现证据。这些是 M7–M9 的交付项。客户工时、采用率、接口和部署条件仍需试点验证。

## 5. 未满足需求的实证、影响与关闭条件

### G01 · 关键版次可仅凭文字理由覆盖，原图仍为 A

**已复现。** 在隔离库中用 DEV-003 创建报价任务。初次本地识别后为 `NEEDS_ENGINEERING_REVIEW`。工程师调用字段修正，将 `drawing.revision` 从 A 改为 B，仅提交修改理由，未上传 B 图或补充证据。原图 SHA-256 不变，原始字段仍为 A，有效字段变为 B。继续任务得到 `READY_FOR_APPROVAL`，审批人按普通流程可提交为 `APPROVED_DRAFT`。

根因是修正统一设置 `human_confirmed`，检查信任有效字段。保留旧值和审计解决了追溯问题，但不能证明原图批准版次已改变。缺失值的有证据补录，与覆盖原文明确存在的矛盾，需要不同处理。

**关闭条件：** 原图 A、要求 B 且没有补充权威依据时，普通字段修正后仍不可进入批准。若项目允许例外，需记录与资料绑定的替代批准依据、单独权限和例外审计。换入有效 B 版图后，原任务应可复核并继续；正常数量澄清不应受影响。[字段修正和校验](../../../apps/api/src/rfq_workbench/file_workflow.py#L412) · [版次规则](../../../apps/api/src/rfq_workbench/costing.py#L86)

### G02 · 参考已变更，通用读取仍暴露可下载的旧草案

**已复现。** 正常 DEV-001 批准并生成 Markdown 后，在隔离库将机时费率从 €60 改为 €61。未重新触发审批或导出时，`GET /runs/{id}` 仍返回 `EXPORTED_DRAFT` 和旧 Markdown。ERP 预览返回 `STALE_DRAFT`，再请求 `POST .../export` 返回 `409 STALE_DRAFT`。前端「下载草案」从已读入的 `run.export.markdown` 生成文件，没有重新请求后端。旧内容因此仍可在此次检测前通过工作台取得。

**关闭条件：** 将“生成有效导出”和“取回当前有效导出”都置于后端新鲜度与权限检查下。费率、模板、规则及知识批准依赖变化后，从新页面或旧页面点击下载均不能取得可被当作当前有效的版本。若保留历史审计文件，需单独标识为已失效历史件。明确谁能下载已批准草案，并测试直接请求和角色切换。已在外部保存的文件通过版本和有效性标记管理，不能由系统事后撤回。[草案新鲜度检查](../../../apps/api/src/rfq_workbench/service.py#L132) · [当前下载实现](../../../apps/web/app/page.tsx#L281)

### G03 · 冻结集的独立样本与默认报价范围尚未对齐

数据计划与 `docs/03-实施与开发/05-M7评测口径.md` 要求独立零件、独立版式及同修订谱系不跨组。运行时 `manufacturing.json` 只有 `PM-BRKT-010` 的批准 B 版、四项尺寸和表面处理条件，知识依据也按料号/版本做匹配。直接换独立料号或尺寸会触发无模板或不适用。这是正确的防错行为，但若把此类样本标为“应正常完成报价”，评测会误将业务范围阻断算成抽取错误；若沿用 DEV-001/002 或只改数量，则没有独立图纸检验。

**冻结前决策：** 分开定义两个评测轨道。抽取和证据轨用独立零件及版式，范围外应拒绝报价可算正确。完整报价轨的正例若要求多个独立零件，就为这些合成件准备独立冻结的批准模板、知识和成本基准，明确是评测配置。若坚持固定单料号，独立端到端报价的结论须限制在该料号，重新写清四个正常案例的独立性和分母。不得将相同图纸改数量当作多个独立零件。[[docs/03-实施与开发/05-M7评测口径|评测边界]] · [适用模板](../../../fixtures/reference/manufacturing.json)

### G04 · 单件毛坯草案没有成为可用输出

早期 MVP、FR-05 及 roadmap 的 `MaterialLine / RoutingStep` 明确区分物料与工艺。系统可显示材料字段、€8/件毛坯成本和四道工序。`Quote` 没有物料行，无法独立交付毛坯规格、每件用量、单位、批次需求及该行来源。外协阳极氧化仅应进入工序/服务，不能作为材料行补数。

**关闭条件：** 按批准模板提供最小的单件毛坯需求行，标明料号/材料、规格与数量单位、用量及批次换算、来源版本和待确认项；支持显示与结构化导出。未知项留空或待确认，换数量可复算。若主动砍掉此项，应同时修改早期 P0 和讲稿，交付主张改为“材料成本项与模板工序”。完整装配 EBOM/MBOM 保留在后续范围。[报价契约](../../../apps/api/src/rfq_workbench/contracts.py#L147)

### G05 · 缺少冻结评测、对照与可复核结果

仓库当前有 6 组开发包、`evals/gold/dev.json`、开发阶段真实抽取记录和 101 项回归测试。尚无已冻结的 12 组独立测试输入及人工核对答案、对应冻结清单、独立评分结果或许可记录完整的外部样本。开发金标与运行输入有隔离约定和测试，不能替代独立评测。服务失败、权限、审批等多项异常已有回归证据，未见文档诱导指令的独立系统评测结果。

**M7 验收：** 冻结 4 正常、3 版次冲突、3 关键缺失、2 单位/费率异常，按 G03 确定支持范围。记录来源、许可、样本谱系、输入/参考/答案 hash、标注者和版本；原始答案不进入模型或检索。故障集独立覆盖越权、诱导指令、错误引用、过期依据、超时恢复、两项控制缺口和重复操作。将字段正确率与覆盖率、引用支持率、阻断召回、误放行、无效阻断、金额一致性分别报告。计时从接收到可审核，同时记录人工核对/修正、调用模式、次数、费用和失败；无法测量就标记未测。3–5 份许可明确的公开外部样本按数据计划单列，不能与合成集混算。

用独立公式复算金额，以人工标注判断字段与证据。人工流程与同输入的直接模型回答可以做小规模对照，区分自动化收益来自提取、规则还是审核。历史报价回测若要报告误差，需独立于当前计价公式的基准和清楚的成本范围；仅用同一费率表生成的“标准报价”只能验证计算一致。 [[docs/03-实施与开发/05-M7评测口径|评测目录说明]] · [[docs/02-方案与规划/03-输入数据规划|输入计划]]

### G06 · 识别到问题后，交接产物仍不完整

工程师可见字段和问题、填写修正原因并继续。问题对象不记录对应证据、业务影响、责任角色和下一步，采购/产能/税运等 `pending` 为静态列表。前端没有可复制的客户澄清清单或明确的“不适用 / 需人工评估”结论。对外承诺被排除在原型之外，实际缺口是内部谁做下一步、需要什么证据。

**关闭条件：** 至少给版次、材料、费率/模板、采购/交期四类问题定义责任角色、证据和建议动作。把硬阻断与预算草案可保留的待确认条件分开。模拟销售交接时能读出需客户提供什么，无适用模板时能明确停止自动准备报价。无需添加完整工单系统。[问题契约](../../../apps/api/src/rfq_workbench/contracts.py#L132)

### G07 · 图纸验证只覆盖报价相关字段的一部分

来源由解析器生成并由后端核对，页级定位清楚。缺少原图区域坐标符合新版 roadmap 接受的降级，不应列为硬性框架缺口。新版范围也提到可读取的所选公差/表面处理及其成本影响，当前有表面处理等值校验，**没有公差字段、规则或成本影响输出**。孔数和孔位由审批人确认，无法作为自动通过的几何结果。人工复核应保留独立结论。应在 M7 区分带文本层的简单图、扫描图和无法支持的标注，报告误读、拒答和人工确认。复杂 CAD、完整 GD&T/DFM 和制造认证继续范围外。[图纸字段](../../../apps/api/src/rfq_workbench/contracts.py#L108) · [[docs/03-实施与开发/09-阶段验收/03-M3证据校验|M3 证据验收]]

### G08 · 诊断、结构化导出与 ERP 预览的交付口径不一致

Markdown 下载和批准快照 JSON API 已实现。用户界面缺独立 JSON 草案下载和失败状态的诊断包，Markdown 也未完整汇出字段级证据、输入文件清单、工艺/物料及所有版本信息。早期 FR-10 说明批准后才生成集成预览，而实际隔离探针在 `READY_FOR_APPROVAL`、工程师角色下得到 `200` 和 ERP `PENDING` 载荷。M6 的只读预览明示待审批，允许工程师先核对映射是合理的业务选择。仍需明确定义它与“可提交的已批准载荷”的区别。

**关闭条件：** 决定保留批准前只读核对还是实施批准后可见。若保留，接口和页面区分待批准预览与已批准输出，且后者受 G02 约束。提供可交付的 Markdown/JSON 草案及任意状态可用的独立诊断内容，诊断无可用报价时也能回查失败阶段、版本和处置。 [[docs/04-项目介绍与展示/05-接口说明|HTTP API]] · [模拟适配器](../../../apps/api/src/rfq_workbench/integrations.py#L88)

### G09 · 受控知识足以保护样例报价，尚不能证明部门级复用

角色、适用范围、批准与期限约束已实现。历史件可以返回差异原因且不会供价。固定项目/工厂、关键词匹配与单模板限制意味着当前没有跨项目实际授权、多工厂选择、自然语言适用性问答质量、历史件相似度证据、变更影响视图，以及人工修正→待审→评测/知识发布的闭环。优先用 M7 的查询和反例检验“是否找到适用条目、是否正确拒用”，再决定需不需要改检索方式。人工反馈先作为待审回归样例，由责任人签核后再发布，避免把错误覆盖扩散为公共规则。真实身份、来源授权、数据外发、日志留存、知识治理和权威系统接入均是客户试点准入项。 [知识选择](../../../apps/api/src/rfq_workbench/knowledge.py#L95) · [[docs/03-实施与开发/09-阶段验收/04-M4知识检索|M4 验收]]

### G10 · 已有面试材料，尚未成为一套可直接交给评审的交付包

README、启动脚本、依赖锁、手册和验收记录齐备；仍要从干净环境按提交说明复现并记录首个闭环。当前默认 `main` 为 `1113230`，树中没有 `apps/`。若只给仓库首页链接，评审者可能看不到可运行原型。现有路线图仍含“原型尚未开发”的早期说明及本机旧路径，演示讲解仍有 95 项/M5 的旧口径，README 缺直接可定位的 Part 1–5 对照。没有找到最终 `docs/business-case.md` 或随交付的备用录屏证据。

**关闭条件：** 交付时指定可检出的提交、分支或发布入口，用一条明确步骤链启动前后端并跑通样例。从空库记录 D1–D5，保留一份样例输入、批准输出、当前架构图和 ROI 说明。准备 12 分钟与 3 分钟稿、可播放的 3–5 分钟备用录屏，回放明确标识模式和来源。对外包保持合成或获准资料，关闭开发故障注入。新评审者能从入口定位 Part 1–5、验收与局限。 [[docs/04-项目介绍与展示/01-项目简介|README]] · [[docs/04-项目介绍与展示/06-启动与运维|运行手册]] · [[docs/05-面试与问答/01-演示讲稿|演示讲解]]

## 7. 非功能要求与推进顺序

| 原型约束 | 已有 | 仍需补证或明确边界 |
|---|---|---|
| 可复现与可维护 | 固定样例、配置、独立金额测试、API 契约、手册 | 复验当前版本的空库启动，统一入口；明确参考资料变更的发布/回滚策略。 |
| 响应与反馈 | 已显示状态、处理、失败原因和重试次数 | 常规识别仍为请求内执行，未见持续节点进度。M7 从受理到可审核测 p50/P95、人工耗时和重试成本；60 秒为目标。 |
| 可靠性与幂等 | 已验收有界重试、手动超期恢复、CAS 和重复导出防护 | 将 G01/G02 纳入跨 API、界面的端到端拒绝测试。模拟超时后的回放演示已通过；真实服务受扰后的同模式恢复仍缺独立测量。 |
| 可追溯与观测 | 输入/输出指纹和版本、证据、识别耗时、模型费用估算、审计 | 并非每节点均有结构化耗时。未生成结果时的费用可能未知；导出与诊断应携带必要版本。 |
| 权限与文件 | 演示角色、作用域拒绝、有界文件大小/页数 | 生产身份、客户项目隔离和获准资料另做试点门槛。受控 CSV/JSON 目前体现为后端参考配置，未提供用户侧通用导入。 |

1. **先关闭能改变安全判定的缺口。** 修复 G01、G02，用两项复现反例作验收。同步确定 G03 的正例范围、G04 的物料草案承诺和 G08 的预览/批准口径。若调整范围，在相关需求文档同时记录取舍。
2. **开始 M7 的独立测量。** 准备并人工核对冻结集；将开发样例、真实/本地识别、回放、系统故障、公开外部样本分别统计。先验证关键阻断、金额、权限和审批无误放行，再报告抽取与证据质量、耗时、费用及剩余风险。
3. **M8/M9 整理业务与交付。** 把 Part 1–5、实测与假设、架构和风险整合为易于评审的说明。补齐确定保留的交付物、演示和复现证据。客户生产前的身份、数据、安全、集成和真实收益继续按阶段准入验证。
