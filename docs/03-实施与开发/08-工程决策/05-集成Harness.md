# ADR 05 · 模拟系统集成 harness

Status · Accepted · 2026-11-11

任务依据为 [[docs/03-实施与开发/M9-集成harness-Codex任务书]]，实现分支为 `codex/m9-integration-harness`，基线 `3d28ab9`。按 T1–T8 保留本地提交检查点。

## 决策

工作台 SQLite 迁移到 v2，新增来源快照、出站意图、派发尝试、回执对账和 API 幂等记录。模拟 PLM、ERP、MES 存放在独立 SQLite 中，状态跨应用重启保留。标识统一使用 **SIMULATED / NO EXTERNAL WRITE**。

计价前在任务事务外读取并保存来源快照，再在事务内核对快照 TTL、来源内容和本地受控依据，记录 `snapshot_refs`。报价对象和既有 `fingerprint()` 编码保持兼容。v1 原任务及事件行原样迁移，旧报价需要重新计价取得来源凭证后才能申请同步。

审批人先请求同步，出站意图与用户审计在同一事务落库。派发器取得带 token 的租约，事务外调用模拟 ERP，返回后凭 token 写回执，再回读目标逐字段对账。结果未知时先按幂等键和业务键查询。租约被回收后到达的结果标记 LATE。背景状态变化只追加事件，用户请求同步提升任务版本。

## 与任务书静态方案的差异

| 项目 | 实际实现与原因 |
|---|---|
| §6.3 把来源版本探测放在 tx1 | 按 §12 的外部 I/O 约束，远端探测和目标读取在 claim 事务外完成。claim 内复核任务批准哈希和来源集合，目标更新携带 `if_match`。派发期间拒绝用户改动该任务，防止修改与发送交错。 |
| UPDATE 在提交前超时 | 目标可能仍保留上一条已验证草案。查询命中相同目标 ID 和预期版本时允许回到 PREPARED，以相同键重试，避免把未提交的更新误判为内容冲突。 |
| 预览兼容 | PLM、ERP 成本与 MES 从假系统读取并保存快照。原接口的 ERP 草案字段继续展示工作台当前有效草案，已送达的目标 ID、回执与差异由新增同步记录提供。 |
| 人工 rebase | 先读取并确认目标当前版本，清除本地报价和批准。重新计价取得来源快照、重新批准后才能生成新意图；目标重复时先交给人工处理。 |
| 评测输出目录 | M7/M9 工具要求新目录。各任务用带任务号和时间的独立目录，避免覆盖旧证据；CI 继续使用干净目录 `var/m7/ci`、`var/m9/ci`。 |
| 读取确认失败 | 读后确认和未知结果查询都有失败预算。预算耗尽进入隔离，保持人工查询、核对与决议路径。 |
| API 执行进程中断 | 请求占位持久化。完成后保存原始响应，重试可读首次结果。若执行中进程退出且尚未保存响应，重试返回 IN_PROGRESS，操作者从任务和意图核对结果。保留期为 24 小时。 |

claim 前探测与真实跨系统提交之间仍有时间窗口。真实连接器需要确认源系统是否能提供稳定版本凭证，以及目标是否能在提交时验证这些凭证。当前故障矩阵验证模拟端口的版本变化、超时、冲突和恢复语义。

## 精度与权威来源

`erp-draft-v1` 明确采用 Decimal 和 HALF_UP 到分，金额通过字符串传输。对账按金额数值、币种、单位、整数数量、行数、每行及全部追踪字段比较。五项成本的批次合计与 `quote.unit_cost × quantity` 允许最多 €0.01 差异。总报价另核对 `unit_price × quantity`，成本与售价分别检查。

规范化只用于新增快照和出站载荷。UTC 时间、空值和 Decimal 的 JSON 表达固定，浮点哈希输入被拒绝。现有 Quote 字段、输入哈希和报价参考哈希保留原口径。

| 真实 ERP 待确认项 | 当前模拟假设 |
|---|---|
| 幂等键和保留期 | 持久保存键及首次请求哈希，重复投递返回首次结果。真实接口需要确定去重作用域、保留期和重复载荷冲突的处理。 |
| 5xx 是否已处理 | 默认按结果未知处理。仅端口明确声明未处理的状态可直接退避重试。 |
| 查询一致性 | 默认强一致。最终一致端口需等满 settle 窗口并再次查询。 |
| 成本参考权威来源 | 当前本地批准参考与 ERP 快照交叉核对。客户接入时由 ERP 成为权威来源，本地文件演进为有版本的缓存。 |
| €0.01 容差 | 当前演示按五条批次成本及分位舍入核对。客户应确认税、币种、逐行及汇总舍入规则后发布下一映射版本。 |

模拟故障可用 `RFQ_SYNC_FAULT_PLAN` 的 JSON 列表配置，支持方法名、故障类型与次数。相同配置签名在同一假系统库只播种一次。P2 的随机模型测试和取消草案补偿留作后续任务。
