# IndustrialMind.ai Option B 输入数据准备计划

> [!important] 执行依据
> [[docs/03-实施与开发/01-实施路线图]] 是本次实施、开发和测试的权威计划。本文补充其输入数据、参考知识、合成方法和评测数据的准备方式；若与旧版 [[docs/02-方案与规划/02-需求分析与方案]] 的技术栈、范围或执行安排不同，以已确定的 roadmap 为准。本文不改变 roadmap 的业务边界，也不建立另一套开发排期。

> [!abstract] 数据策略
> **主线演示使用自主设计、相互一致的合成业务包；图纸理解能力用许可明确的公开样本单独检查；同时争取招聘方提供少量获准的脱敏资料。**
> 首期不需要大规模训练集，数据主要用于运行上下文、业务规则、现场演示和独立评测。公开图纸通常不附带对应 RFQ、工艺、成本和标准答案，因此不能直接替代完整业务包。

> [!info] 当前状态
> 已核查部分公开资料入口和 IndustrialMind 官网演示入口，尚未下载整理公开数据、建立公司账户、获取客户授权、制作合成图纸或生成评测结果。下文的文件名、数量与验收条件均为实施计划。

## 1. 与实施范围的对应关系

首版保持 roadmap 已确定的范围：执行器配套的单件机加工安装支架、德国单工厂、EUR、mm。一个任务按一份获准的当前图纸版本计算；A/B 版是版本检查与变更测试资料，不能同时混入一个未经确认的成本快照。

| 入口 | 必备输入 | 输出所需依据 | 数据边界 |
|---|---|---|---|
| `prepare_quote` | RFQ、当前图纸、数量、要求修订版、币种 | 材料目录、有效费率、适用工艺模板、规则与证据 | 只形成可审核内部预算草案；采购、产能、交期与合同条件未验证时保持 `pending` |
| `review_drawing` | 图纸；涉及 RFQ 一致性检查时附 RFQ 上下文 | 可观察字段、受控检查规则 | 只读问题与证据；不计算价格，不自动批准，不宣称完整 GD&T/DFM 验证 |
| `search_knowledge` | 明确问题、项目/工厂/产品族范围 | 有来源、版本、批准状态和有效期的资料 | 返回适用依据和差异；检索文本不能直接成为价格来源，不能写入公共知识 |

**数据之间必须能关联。** RFQ、图纸、料号、工艺适用条件和成本单位必须指向同一零件与明确版本。目录里的零售价格不能直接当成客户工厂的制造成本；历史案例相似也不意味着当前工艺和费率有效。

## 2. 需要准备哪些数据

### 2.1 用户实际提交的数据

| 数据 | 必备字段或内容 | 首期形式 | 准备方式 |
|---|---|---|---|
| RFQ 询价 | RFQ ID、零件号、要求修订版、数量、币种、附件引用；期望交付时间和特殊要求如有则保留 | Markdown/文本邮件或 PDF；按实现支持的格式导入 | 根据统一零件规格编写；明确标注合成客户和合成数据 |
| 二维工程图 | 图号、修订版、材料、单位、外形与孔位等所选关键尺寸、明确给出的公差与表面处理 | PDF，原型以简单 1–3 页包为目标 | 自主 CAD/矢量出图；文本层与页图均保留 |
| 澄清/变更信息 | 原 RFQ/零件引用、变更内容、适用版本、确认依据 | 表单输入或受控澄清文本 | 为修正、暂停恢复和审批失效场景合成 |
| 用户任务 | 三种明确任务类型或自然语言请求 | UI 按钮与文本 | 正常请求、含糊请求、缺附件请求各有样例 |

不要要求用户直接提交标准答案 JSON 来代替真实抽取。标准答案属于评测资料，运行输入仍应是用户可阅读的 RFQ 和工程图。

### 2.2 系统使用的受控参考数据

| 数据 | 最小内容 | 建议初始规模 | 关键约束 |
|---|---|---|---|
| 材料与毛坯目录 | 料号、材料、名称、计量单位、工厂、产品族、状态与来源 | 约 5–10 条，含不适用反例 | 单件毛坯/原材料清单不等于完整装配 BOM |
| 工艺模板 | 模板 ID/版本、适用条件、工序、准备时间、单件时间、设备类别、批准状态 | 1–2 个适用模板，另加至少 1 个不适用或未批准模板 | 全部演示参数；不能声称经客户批准或可以直接生产 |
| 成本与费率 | 毛坯成本、加工与检验费率、外协费用、币种、单位、工厂、生效/失效时间、版本 | 1 套完整有效费率，配过期和单位/币种异常版本 | 由确定性计算读取，不从自由文本 RAG 答案取价格 |
| 检查规则 | 规则 ID/版本、适用范围、输入条件、严重性、处置与责任人类型 | 约 8–12 条明确规则 | 仅实施有依据的检查，不编造工业认证结论 |
| 工程知识条目 | 来源、内容、适用产品族/工厂、批准状态、有效期、引用位置 | 约 8–12 条；与模板、规则可共享来源 | 至少覆盖适用、过期、不适用、权限不符和无答案情况 |
| 历史案例 | 历史零件/版本、材料、模板、报价快照、有效期、与当前件差异 | 约 3–5 个小型案例即可 | 支持不适用历史件测试；首版无需为此建立大规模向量库 |
| 作用域与演示角色 | 项目、工厂、可见资料、允许操作、演示账号 | 主项目与至少一个隔离项目 | 明确是本地演示身份；不把角色切换宣称为企业 SSO |
| 集成样例 | PLM 版本元数据、ERP 成本/报价映射、MES 工时反馈字段 | 各一个契约与模拟样例 | 不伪造真实系统连接或成功回执；MES 样例不影响未验证的生产判断 |

### 2.3 评测专用数据

每个测试案例至少有：预期字段与单位、支持该字段的文件/页码/原文、可用时的区域坐标、应发现的问题、应使用或排除的知识条目、正确成本结果、审批条件和期望流程行为。

真值与期望结果单独保存，不进入模型输入、检索索引或运行时业务目录。实现不能根据案例 ID 返回预制答案；实时、回放、规则计算与人工补录都要明确标识。

## 4. 如何合成，同时保证一致性

1. **先定义受支持零件规格。** 固定零件号、修订版、单位、材料、几何和可观察工程要求，记录适用模板。不要一开始加入复杂曲面或完整装配。
2. **用确定性绘图工具出图。** 采用 CAD 或矢量脚本生成图纸，人工核对视图、尺寸线、标注和标题栏的一致性。不用图像生成模型随意绘制需精确读取的工程标注。
3. **由同一规格制作正常业务文件。** RFQ、图纸和料号关联一致；语言模型可协助改写询价措辞，但不得自行改变数字、材料或版本。
4. **单独准备费用与工艺假设。** 工时来自演示模板，费率来自受控表；不让模型根据图形猜测实际加工时间。每项假设都可以追溯和替换。
5. **从正常样例派生明确反例。** 每次有意改变一个因素，如替换旧版图、移除材料、使用过期费率或改变数量；记录注入的异常与预期处置。不要意外制造多处矛盾而无法定位失败原因。
6. **独立核对真值。** 字段和证据人工核对；金额用独立计算校验；图纸工程适用性不足以验证时明确标为演示假设。不能仅让生成内容的同一个模型给自己评分。
7. **冻结评测版本。** 固定文件 hash、生成脚本/模板版本与答案。冻结集一旦用于调提示词或规则，就转为开发数据，再准备独立测试样本。

> [!warning] 合成数据证明的范围
> 它可以验证抽取与证据流程、规则、计算、审批、暂停恢复和错误处理。它不能证明真实工厂的加工可行性、客户 RFQ 适用率、生产可靠性或实际工时收益。公开图纸与客户脱敏样例分别用于补充版式变化和业务适用性验证。

## 5. 数据集规模与划分

| 数据组 | 计划规模 | 用途 | 完成标准 |
|---|---:|---|---|
| 开发集 `DEV` | 6 组 RFQ 包 | 正常闭环、版本冲突、缺失信息、数量变更、知识适用与任务入口调试 | 每组输入、参考数据与人工核对的期望行为齐全 |
| 冻结集 `EVAL` | 12 组 RFQ 包 | 4 正常、3 版本冲突、3 关键缺失、2 单位/费率异常 | 第一次正式评测前冻结，不参与后续调优 |
| 外部样本 `EXT` | 3–5 份许可明确的公开图纸 | 检查不同版式下的提取、证据与拒答；不强行套入支架报价 | 记录来源、许可和手工标注范围；无工艺/成本依据就不报价 |
| 系统异常集 `FAULT` | 按关键风险建立案例 | 超时、重试、旧审批、越权查询、重复导出、诱导指令、任务歧义、无适用模板/历史件 | 每个行为有可检查的状态与事件结果；不混入字段准确率分母 |

这是一套小规模原型验收数据，不是统计上代表真实客户的样本。

**划分规则：** 同一零件的不同版本、同一图纸的清晰/模糊变体放在同一数据组，不能以近重复样本跨组获得虚高表现。保持单一支架产品族，但冻结集应包含独立零件、尺寸组合和图纸版式；不能只把数量换一下就声称是独立图纸测试。公开外部样本单独报告，区分“输入不在支持范围”和“支持范围内抽取失败”。

知识与路由至少准备以下对照：适用且有效、同类但材料不同、过期、未批准、其他工厂、权限不匹配、未找到依据。知识目录可很小，但这些判断应能真实执行。

**M7 两类评测：** 抽取和证据使用独立零件与版式，范围外输入仍可有正确的字段与拒绝结论。端到端报价的正常例必须随冻结包提供获准的工艺、材料、费率与知识参考，以及独立计算的金额和毛坯批次数量。按案例隔离加载评测参考，合成评测配置不扩大演示范围。各类结果分别统计，具体口径见 [[docs/03-实施与开发/05-M7评测口径|评测边界]]。

不要在未确认许可时改写制造商图纸的 Logo、料号或尺寸，并把改写结果作为自己的新图纸。主线零件应自主设计；外部资料保持来源清楚。

## 7. IndustrialMind 是否有官方输入数据

### 7.1 本次核查结论

- 官网有 [Drawing Parser 演示入口](https://www.industrialmind.ai/en/tools/drawing-parser)。本次浏览器检查时，需要注册/登录；页面提示免费账户有 5 次解析机会。这是当日页面状态，不保证长期不变。
- 在未登录可访问的官网与公开搜索范围内，**未找到可下载的完整 RFQ＋图纸＋成本表＋标准答案数据包**。未检查登录后是否存在样例库，不能据此断言公司内部没有可提供的数据。
- 官方[定制液压缸报价案例](https://www.industrialmind.ai/en/use-cases/ai-assisted-quotation-generation-for-custom-hydraulic-cylinders)可用来理解业务关联，不是可直接导入的数据包。
- 搜索发现的 [同题个人演示仓库](https://github.com/kamsiya/industrialmind-rfq-agent-demo)自称面试原型，并明确说明采用合成输入。它不属于公司官方数据来源，不作为本项目的公司授权或客户真实性证明。

### 7.2 向招聘方申请什么

建议请求很小、容易提供的一组资料：1–3 份获准使用的脱敏 RFQ、对应图纸、期望输出，以及可虚构的工艺/费率模板。询问是否允许外部模型处理、现场演示和源码仓库分发；这三种用途分别确认。

可由用户发送的请求草稿：

> 为了让 Option B 原型更贴近贵公司的实际工作流，能否提供 1–3 份允许用于面试的脱敏 RFQ 和对应图纸，以及期望输出示例？成本与工艺参数可以使用虚构值。如果没有可提供的样例，我会使用自主构建、明确标注的合成数据。也请说明所提供资料是否允许通过外部模型 API 处理、用于现场演示或随项目代码分享。

此请求尚未发送。等待回复期间可继续合成数据与原型工作；获得公司资料后，新增独立案例并保留来源和使用边界，不覆盖现有冻结样例。

## 8. 来源记录、目录与运行隔离

每个数据包记录以下信息：`case_id`、`origin_type`、来源链接或作者、许可/使用范围、获取日期、文件 hash、零件与版本、项目/工厂/产品族、数据分组、标注人、标注版本、限制说明。

`origin_type` 至少区分 `synthetic`、`public_reference` 和 `company_provided`。资料“已脱敏”与“允许外发/公开分享”分别记录，不能相互替代。

```text
  authoring/                 # 自主零件规格与生成脚本；不供模型读取
  dev/                      # 开发用 RFQ、图纸、澄清资料
  reference/                # 演示目录、规则、模板、费率与知识
  integrations/             # PLM/ERP/MES 模拟契约与样例
  manifests/                # 来源、许可、hash、范围与分组
evals/
  inputs/                   # 冻结输入与许可明确的外部样本
  gold/                     # 标准答案与人工核对证据；禁止进入检索
  faults/                   # 故障注入与关键系统行为案例
  results/                  # 实测结果、版本、失败与耗时费用
```

运行时仅加载当前任务授权输入与明确允许的 `reference` 内容。评测程序可以读取 `gold` 比较结果，模型、Agent 和知识检索不能读取它。外部样本存在分发限制时，只记录获取指引与 hash，不随公开仓库打包。

## 9. 对齐 roadmap 的实现里程碑

| Roadmap 里程碑 | 数据准备输出 | 进入验收的条件 |
|---|---|---|
| M0 范围与数据契约 | 正常业务包、主要反例、schema、来源记录、数据划分方案 | 输入与人工核对真值可独立阅读；明确假设、支持范围和冻结集隔离 |
| M1 确定性后端核心 | 有效费用明细、模板、100/500 件标准计算、审批依赖样例 | 每项费用、单位、版本和公式可独立复算 |
| M2 首个端到端核心 | 正常 RFQ＋B 图、冲突 RFQ＋A 图、可确认的修正资料 | 实时抽取、冲突暂停、修正、计算、审批与导出能用真实文件跑通 |
| M3 抽取证据与稳健性 | 字段证据标注、空值/模糊资料、提取配置记录 | 证据能回到实际文件；未知字段不被补造 |
| M4 有限审查与知识 | 适用/过期/未批准/跨工厂/无权限知识、历史反例 | 过滤与阻断有正反例；价格不取自检索叙述 |
| M5 Orchestrator 与 HITL | 三入口请求、歧义请求、变更与审批角色样例 | 路由、暂停恢复和审批失效有可检查的预期结果 |
| M6 可靠性与集成预览 | 超时、重试、重复操作、集成预览与回放来源 | 可诊断错误，不产生重复有效输出；模拟与实时明确区分 |
| M7 独立评测 | 冻结集、外部样本、系统异常集、人工核对答案 | 按层报告分母、拒答、误报、失败、延迟和费用，不外推客户收益 |
| M8 方案与商业论证 | 实测摘要、假设与未验证数据清单 | 原型结果和客户业务假设分开呈现 |
| M9 演示与交付 | 可重置演示包、原始文件、评测报告与备用回放 | 干净启动可复现，现场改数量或选冲突案例可操作 |
