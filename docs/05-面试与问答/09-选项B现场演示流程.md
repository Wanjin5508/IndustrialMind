# 选项 B · 现场演示流程

对应 [[docs/01-原始说明/01-设计挑战#选项 B：通过 AI 辅助编程构建原型（Vibe Coding Prototype）]]。用 PrecisionMotion 的合成询价展示一套能运行的工程工作台。主线是 **100 件询价 → 证据复核 → 计价 → 审批与导出 → 模拟 ERP 对账 → 客户改量**。最后用独立任务展示错版图纸如何阻断、补件后如何恢复。

建议主线 **12 分钟**，另留 **2 分钟**做 500 件的 ERP 更新。被要求缩短时走本文最后的 3 分钟版本。所有价格均为演示样例的内部预算，ERP 是模拟目标。

## 系统架构与客户系统边界

![[docs/04-项目介绍与展示/10-展示附件/08-功能模块与系统边界.png]]

上图展示工作台基础数据流。独立的「报价 Agent」入口从工程请求和混合附件开始，模型选择分诊、读取、抽取、查知识、计价或提问工具，工作台校验权限并执行。可用工具和边界见 [[docs/05-面试与问答/10-AI-Agent设计与实现#1.1 报价 Agent 如何选择工具]]。

从左上沿蓝色箭头讲主线。工程师提供 RFQ 和图纸，任务编排按目标选择报价、图纸审查或知识查询。候选字段带来源进入工程校验，只有通过校验的报价任务才会使用受控知识与来源快照计价。审批人批准当前版本后，可以下载内部预算或另行请求模拟 ERP 同步。

| 工作台外的接口          | 请求与返回                                                              |
| ---------------- | ------------------------------------------------------------------ |
| 外部模型服务           | 在线识别发送文本与 PDF 页图，返回候选字段及来源 ID。工作台核验后才使用这些值                         |
| 客户 PLM · 只读      | 按零件号与工厂读取发布版次和有效期，用于核对图纸                                           |
| 客户 ERP · 读取成本依据  | 按材料与工厂读取成本、费率及来源版本，与本地受控依据交叉核对                                     |
| 客户 MES · 只读      | 按零件号与工厂读取计划与观察工时，随草案保存来源快照                                         |
| 客户 ERP · 草案写入与查询 | 发送已批准草案的零件、版次、数量、金额和成本明细，创建或按目标版本更新。回执给出目标 ID 与版本，随后查询目标实际载荷，逐字段对账 |

> 话术：“蓝框是工作台。在线模式经绿线把资料交给模型抽取候选字段，证据核验、计价和审批都在工作台内。右边虚线标出客户系统接入点。PLM 和 MES 只读，ERP 既供成本参考，也接收批准后的内部草案。当前演示用本地适配器模拟这三套系统。同步完成时，我会指出目标 ID、版本和回读结果。”

## 1. 开场前准备

### 运行环境与演示账户

1. 在项目根目录打开两个 PowerShell 窗口。若使用新的演练目录，先在原服务控制台停止占用相同端口的进程。
2. 窗口一启动 API。每轮完整彩排用新的数据目录，例如把 `rehearsal-01` 改成 `rehearsal-02`。演示主线沿用费率 A。

   ```powershell
   $env:RFQ_DATA_DIR = 'var/option-b-rehearsal-01'
   $env:RFQ_RATE_PROFILE = 'A'
   .\scripts\start-api.ps1
   ```

3. 窗口二运行 `.\scripts\start-web.ps1`。先访问 [API 健康检查](http://127.0.0.1:8000/health)，再打开 [RFQ 工作台](http://127.0.0.1:3000/)。确认左上角是「德国工厂 / DE-DEMO」，右上「当前角色」选「工程师」。启动参数与常见故障见 [[docs/04-项目介绍与展示/06-启动与运维]]。
4. 文件选择器定位到 `docs/05-面试与问答/05-演示输入材料`。浏览器另开 03 客户澄清件。提前在现场服务使用的数据目录里准备独立的备用任务，分别保留 100 件已对账、500 件待审批和错版阻断三个状态，记录任务 ID，打开已下载的 Markdown 和 JSON。若备用任务在另一套数据目录，提前保留它们的页面截图和导出件。
5. 排练时确认两份 PDF 的字段能提取、100 件结果为 **€2,547.00**、同步显示 `MATCH`。来源快照默认有 15 分钟有效期。若备用草案要现场派发且来源已过期，用工程师角色在「成本草案」点「重新计算」，再切审批人批准。

**用 PDF 演示客户改量。** 本文主线用「稍后上传」从 01 + 02 开始。03 是同一张询价的后续澄清。通过「工程确认与补充依据」记录新值、原值、修改原因和操作人，原 RFQ 仍能回查到 100。当前工作台保存的是**人工确认与原因**，澄清 PDF 本身由工程师在外部打开和查阅。上传到「补充 / 替换 RFQ」会替换该任务的主询价及其抽取字段，因此按主线演示时把 03 留在工作台旁。

## 2. 现场逐步操作与话术

### 00:00–00:45 · 交代案例、角色和终点

**操作。** 停在「任务总览」，指一下「当前角色」和「德国工厂 / DE-DEMO」。用手中的 01、02 说明待处理材料。

**话术。** “PrecisionMotion 的工程师收到一份执行器安装支架的询价和一张图纸。我扮演工程师接单，之后切到审批人。我们先做出一份能复核、能导出的内部预算，再模拟同步到 ERP。最后我会改一次数量，再交一份错版图纸，让大家看看异常是怎么处理的。”

### 00:45–02:25 · 创建任务、上传并处理

1. 在「任务总览 → 新建任务」选择「准备内部报价」，样例下拉选「稍后上传」。请求说明填 `选项B-100件主线`，点击「创建任务」。
2. 在新任务的「补充 / 替换 RFQ」选 01，在「补充 / 替换图纸」选 02。点击「保存资料」。记下任务 ID，后面切换角色时用它定位。
3. 选择「本地文本识别」，点击「继续处理」。正常进入「待审批」。若停在工程复核，按提示核对相关字段。

**话术。** “我在创建时明确选择准备内部报价。‘继续处理’会按这个任务的目标读资料、校验，然后尝试计价。这里 RFQ 要 B 版，收到的图纸也是 B 版。后面换成 A 版时，我会做一遍同样的操作。”

### 02:25–04:05 · 核对原件和受控知识

1. 打开「资料与证据」。依次指出客户要求版次 B、图纸版次 B、材料 `Al-6061-T6` 和数量 `100`。点击材料或版次旁的「依据」，展开来源，必要时打开原尺寸页图。对照 PDF 页上的字段读出一项实际证据。
2. 打开侧栏「受控知识」。使用页面预设的 `PM-BRKT-010` 场景，材料选 `Al-6061-T6`，图纸版次选 B，关键词留空，点「查询受控知识」。选一条当前可用的模板或费率，再选一条仅供参考的记录，展示适用性、版本或拒用原因。
3. 如果上一段使用了 Agent，将工具轨迹中的依据版本与成本页相应记录对照。打开对应字段原页，说明工具返回的依据如何进入报价。

**话术。** “我先对两份原件。这里的材料字段连到图纸上的原文，能直接打开给工程师看。再看右边这条加工模板，它适用于这个零件和版次。历史记录也能查，只有当前批准且适用的版本能进这份草案。”

### 04:05–05:05 · 展开成本和物料需求

1. 进入「成本草案」，确认 **100 件、€25.47/件、€2,547.00**。
2. 展开费用明细，指一次准备费和对应费率版本。指出毛坯 `Al-6061-T6`、`82 × 52 × 13 mm`、每件成品用一件、批次 100 件。
3. 让画面停在费用与结果上，留出几秒给面试官核算。

**话术。** “这批的准备费是 1.5 小时乘每小时 €60，共 €90。分到 100 件，每件 €0.90。加上可变成本 €18.20，单位成本 €19.10。按 25% 目标毛利计算并将单价舍入到分，得到 €25.47。模板也给出毛坯规格和批次用量。运输、税费和产能还要另外确认。”

![[docs/05-面试与问答/09-演示截图/02-正常报价100件.jpg]]

*费率 A 的 100 件对照。按顺序指出数量 100、单位成本 €19.10、单位报价 €25.47、总额 €2,547.00。截图截取自已完成导出的备用任务。*

### 05:05–06:35 · 审批和下载

1. 将「当前角色」切为「审批人」。回「任务总览 → 最近任务」，按 ID 打开 100 件主任务。
2. 进入「审批与审计」。核对数量、版次和计价依据，勾选复核确认，填写 `核对 B 版、材料和计价依据，批准用于内部预算`。点击「批准当前草案」。
3. 点击「生成导出文件」，随后依次点「下载草案（Markdown）」和「下载草案（JSON）」。
4. 打开其中一个下载件。Markdown 展示数量、总价、物料与成本依据，JSON 展示 `quote.material_lines` 和 `approval`。返回审计页指出批准和导出记录。

**话术。** “我切到审批人，复核的是刚才这份 100 件草案。批准绑定具体的草案内容。Markdown 适合工程和商务一起看，JSON 里保留结构化的成本、毛坯和审批信息。现在手上已有可交给内部同事的文件。”

![[docs/05-面试与问答/09-演示截图/10-批准与导出入口.jpg]]

*批准后生成导出文件，两种下载按钮出现在同一审批页。下方审计时间线可查操作。*

### 06:35–08:00 · 同步到模拟 ERP 并对账

1. 保持审批人角色，回主任务「成本草案 → ERP 草案同步 · 模拟」。备注填 `同步 100 件内部草案`，点击「请求同步」。
2. 指出「待派发」，再点「派发一次」。等到「对账通过」，确认最近对账为 `MATCH`。记录屏幕上的 **目标记录 ID 和版本 1**。
3. 展开「来源快照」和「意图与尝试详情」。指明一份来源快照、这次创建意图和返回的目标版本。页面上保留 `SIMULATED / NO EXTERNAL WRITE` 标识。

**话术。** “请求同步会先保存一条出站意图，派发才调用模拟 ERP。收到回执后，系统还会读回目标草案。现在是 MATCH，说明回读内容与发出的草案相符。我们记下目标 ID，改量后会继续更新这条记录。”

![[docs/05-面试与问答/09-演示截图/03-模拟ERP对账.jpg]]

*首次同步为创建草案，目标版本 1。查看「最近对账 MATCH」和模拟环境标记。*

### 08:00–09:45 · 客户改量、旧审批失效、重新计价

1. 打开 03，指出 `PM-INT-001` 从 100 件澄清为 500 件。切回「工程师」，在「任务总览 → 最近任务」按 ID 重新打开**同一个** 100 件主任务，取到同步审计写入后的最新任务版本。
2. 进「资料与证据 → 工程确认与补充依据」，选择「数量」，确认值填 `500`，依据填 `客户澄清 PM-INT-001 clarification 01，批量由 100 改为 500`。点「保存并重新校验」。
3. 在字段里展示原值和确认值。在「成本草案」或「审批与审计」查看原草案与当前审批已清除。回「任务总览」点「继续处理」，确认 **€24.51/件、€12,255.00，待审批**，毛坯批次用量为 500。
4. 如有两分钟，切审批人，复核并批准新草案。可再次导出。同步备注填 `按客户澄清更新为 500 件`，请求同步并派发。确认「更新草案」、**同一目标 ID、版本 2、MATCH**。保留两次意图供比较。

**话术。** “客户只改了数量，我把澄清留在原任务的数量字段和审计里。原批准对应 100 件，改动后这份批准立即失效。准备费仍是 €90，分到 500 件变为 €0.18，因此新单价是 €24.51。客户改量以后，审批人要重新确认这份预算。”

### 09:45–11:30 · 版次冲突与补件恢复

1. 切到「工程师」。新建第二个「准备内部报价」任务，请求说明填 `选项B-版次冲突`。上传 **04 RFQ + 05 A 版图纸**，点「保存资料」，用「本地文本识别」点「继续处理」。也可从前面的 Agent 错版任务打开工程记录查看。
2. 进「资料与证据」，并列指出 RFQ 要 B 与图纸标 A，定位 `REVISION_CONFLICT`。当前模板也会报告 A 版无批准依据。打开「成本草案」，确认此任务没有可审批草案。
3. 回同一任务「任务总览」，在「补充 / 替换图纸」只选 **02 B 版图纸**，点击「保存资料」。再次点「继续处理」，查看同一任务恢复到待审批和 **€2,547.00**。
4. 如果时间只够做负例，停在阻断状态，口头交代补件操作。面试官追问补件恢复时，再用同一任务继续。

**话术。** “这里客户明确要 B 版，随信附来的却是 A 版。工程师先看到两个原始值，然后看到冲突，任务停在复核。现在我补上客户给的 B 版文件。同一个任务重新检查并生成草案，补件和重新处理都留在审计里。”

*错版任务的输入是 04 RFQ 和 05 A 版图纸。重点指向 `REVISION_CONFLICT`，再下滑比对结构化字段的 B 与 A。*

*补件后「文件抽取」显示 04 RFQ 和 02 B 版图纸。回「成本草案」确认该任务恢复计价并等待审批。*

### 11:30–12:00 · 收尾

**操作。** 停在 B 版恢复后的待审批草案，或返回主任务对账结果。

**话术。** “我把附件识别、确定性计价和 ERP 派发拆开，因为三步的错误处理不同。识别要回查原件，计价要能复算，派发要能确认目标有没有写入。刚才的正常单、改量和错版展示了这三个边界。接入客户环境时，我会先用获授权的样本和 ERP 沙箱验证映射、并发条件和查询能力。”
