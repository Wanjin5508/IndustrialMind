# 前端产品文案

界面面向工程师、报价人员和审批人员。只呈现任务数据、操作名称、业务状态、必要的输入限制和可执行的错误提示。

- 禁止口号、设计理念、自我辩护和能力声明，例如“让每个判断有依据”“创建任务不会调用模型”“文字说明只作上下文”。
- 不在业务页面解释模型权限、后端鉴权、实现方式或开发里程碑。技术诊断收进按需展开的详情；架构原理写入技术文档。
- 按钮直接命名操作，如“保存资料”“替换图纸”。提示直接说明要处理的问题或下一步。
- 保留准确的审批范围、资料适用性、待复核项目、文件限制与错误信息；不要用文案删减掩盖业务状态。
- 页面检查包括 API 返回的任务提示和样例摘要，不能只检查静态 JSX。样例标识集中呈现，避免重复提醒。
