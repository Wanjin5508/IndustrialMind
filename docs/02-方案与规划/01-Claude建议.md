## 原型：只做一条垂直链路

题目给的数据是 15,000 份 RFQ、50,000 张图纸，说明最值得做的是 **RFQ → 图纸理解 → BOM 与工艺路线 → 报价草稿**。这条链路量大、重复、直接影响交付周期和赢单率，也正好对应他们官网列出的图纸理解、报价、BOM、工艺规划这几项能力。

```
RFQ 邮件 + 图纸(PDF/图片)
  → ① 图纸理解 Agent（视觉 LLM 抽取结构化字段 + 置信度 + 出处）
  → ② 规则校验（缺材料、公差与单位是否合理）
  → ③ 工艺规划 Agent（检索相似历史零件 + 工序库，LLM 提方案，规则校验可行性）
  → ④ 报价工具（确定性成本模型，LLM 只负责调用，不做算术）
  → ⑤ 工程师审核界面（可修改，修改记录存为反馈）
  → 输出：BOM、工艺路线、报价草稿、审计记录
```

**几个能拉开差距的设计点**

1. **用合成图纸做评测。** 没有真实图纸，可以用 Python 生成带尺寸、公差、材料、表面粗糙度标注的合成图纸，同时保存真值。这样你可以报出**字段级准确率**，用数据说话，这正好体现你的数据科学背景。
2. **LLM 不做计算。** 成本、工时、材料用代码计算，LLM 只负责理解和起草。这点要在方案里说明。
3. **每个字段都带置信度和出处**，低置信度的会被标红，让工程师重点复核。
4. **审核结果回流。** 工程师的修改存下来，作为回归测试集和后续的 few-shot 示例，体现持续改进。
5. **做一个历史回测**：用几十个合成的历史 RFQ，对比 AI 报价和"真实"报价的偏差。这是你方案里"影子模式"的缩小版。

**技术选型**：Python + Pydantic 结构化输出 + Claude 或 Gemini 的视觉能力，界面用 Streamlit 或 Gradio 即可，存储用 SQLite 加一个小型向量库。你之前做过基于 pgvector 的知识引擎，如果它能直接复用，检索那一层可以省时间；否则就用轻量方案，别为这个测评去搭环境。

**编排框架要能解释**：这个流程基本是线性的，加上一两处人工审核，用普通 Python 函数加状态对象就够了。只有需要中断、恢复这类审核机制时，LangGraph 才有价值。能说清楚"为什么选或不选"，比用了某个框架更重要。

|Part|要点|

|3 技术架构|数据接入层（ERP/PLM/MES，先只读）、文档理解层、知识库、编排层、审核闸门、审计日志。强调**德国客户的数据安全**：欧盟托管或私有部署，图纸属于核心知识产权。|
|4 商业论证|给出"保守、基准、乐观"三档，并用公式列出假设。|
|5 路线图|见下文。|

**ROI 的写法**：先写假设再算，例如"每份 RFQ 平均占用工程师 X 小时 × 15,000 份 × 可自动化比例 × 工程师综合成本"，再加上报价周期缩短带来的赢单率提升，最后扣除平台和实施成本。数字用假设并标明，不要写得过于精确。另外，德国企业有劳资委员会，建议用"释放产能、重新分配"的说法，而不是"节省人头"。

**路线图建议**：

- **Phase 1（0–3 个月）**：选一条产品线（比如减速机），3–5 名工程师，**只读加影子模式**，拿历史 RFQ 回测，量化 AI 与人工的差距。
- **Phase 2（3–9 个月）**：部门推广，接入 ERP/PLM，增加工艺规划和知识检索。
- **Phase 3（9–24 个月）**：覆盖德国、波兰、中国三个工厂，支持多语言图纸与不同标准（DIN、GB 等），再接入变更管理和 MES 的根因分析。

**风险部分**：幻觉（靠人工审核加规则校验）、数据质量、CAD 格式多样、知识产权、组织接受度，以及这套系统不直接控制产线，只提供分析和建议，这点和你之前的疑问是一致的。

## 提交时的注意点

- **可复现**：一条命令能跑起来，附样例输入输出，演示失败时有一段 3–5 分钟的录屏兜底。
