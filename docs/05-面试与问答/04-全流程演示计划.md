# RFQ 工作台全流程演示计划

12 分钟主线从实际上传开始，走完证据核对、受控计价、审批下载、数量变更和错版恢复。最后切换到单图纸审查和知识查询，展示三个入口各自的输出。讲解与架构图见 [[docs/05-面试与问答/01-演示讲稿]]。题目五部分和商业论证见 [[docs/04-项目介绍与展示/11-方案答卷]]。

## 1. 台前准备

1. 按 [[docs/04-项目介绍与展示/06-启动与运维]] 启动 API 和工作台。为演练选一个未使用的 `RFQ_DATA_DIR`，例如 `var/interview-rehearsal-01`。打开 `http://127.0.0.1:3000`，确认当前角色为**工程师**。每次完整演练用新目录，保留上一次的任务和导出。
2. 把下面六份 PDF 放在同一个易定位的文件夹，按编号排列。提前打开 03 数量澄清单、方案答卷和 M7 报告三个标签页。新建任务的**请求说明**可分别填“主线 100 件”“错版演示”“单图纸审查”和“受控知识查询”，方便从最近任务找回。
3. 若准备展示现场在线调用，先确认「在线图文识别」可选且服务正常。后半段用**本地文本识别**即可复现同一组文件的确定性流程。短版另准备一个已导出的正常任务和一个仍停在 A/B 冲突的任务，两者都用下表文件创建。

| 编号 | 材料 | 用在何处 |
|---|---|---|
| 01 | [RFQ · 100 件](05-演示输入材料/01-RFQ-100件.pdf) | 主线 RFQ，要求 PM-BRKT-010 B 版、100 件、EUR |
| 02 | [PM-BRKT-010 B 版图纸](05-演示输入材料/02-PM-BRKT-010-B版.pdf) | 主线图纸、错版恢复的替换件、单图纸审查 |
| 03 | [客户数量澄清 · 500 件](05-演示输入材料/03-客户数量澄清-500件.pdf) | 在同一任务核对并人工确认新数量，保留原 RFQ |
| 04 | [RFQ · 版次冲突](05-演示输入材料/04-RFQ-版次冲突.pdf) | 独立询价，仍要求 B 版，和 05 配对触发冲突 |
| 05 | [PM-BRKT-010 A 版图纸](05-演示输入材料/05-PM-BRKT-010-A版.pdf) | 错版场景首次上传 |
| 06 | [PM-BRKT-010 B 版图纸 · 材料缺失](05-演示输入材料/06-PM-BRKT-010-材料缺失.pdf) | 加演时与 01 配对，展示未知材料阻断 |

RFQ 与图纸均为合成资料。PDF 含可搜索文本，图纸包含视图和尺寸，既可展示页图，也支持本地文本识别。文件夹中的数字表示拿取顺序。

## 2. 12 分钟现场流程

| 时间 | 操作 | 观众应看到什么 |
|---|---|---|
| 0:00–1:15 | 用一张架构图讲清 RFQ 工作台。打开 01 和 02，让面试官先看到两份原件。 | 业务目标是把客户输入变成可核对的内部预算。模型负责读取，程序负责校验与算价，审批人负责批准。 |
| 1:15–2:45 | 在「任务总览 → 新建任务」选择「准备内部报价」，样例选「稍后上传」，点击「创建任务」。将 01 选为 RFQ，02 选为图纸，点「保存资料」。选「在线图文识别」或「本地文本识别」，点击「继续处理」。 | 开始时任务等待资料，处理后生成两份文档的字段和证据，正常结果停在待审批。选择在线时展示任务实际识别方式和调用记录。 |
| 2:45–3:45 | 切到「资料与证据」。先对比 RFQ 的要求版次和图纸版次，再点材料的「依据」，打开原尺寸页图。 | 两份文件均为 B。材料是 `Al-6061-T6`，证据可回查到图纸页及对应文本。孔位、公差与可制造性仍属人工复核事项。 |
| 3:45–4:30 | 切「受控知识」，保留默认料号、材料与版次，关键词留空，点「查询受控知识」。 | 工程师可见 8 条，其中 3 条可用于计价。展示历史与过期记录卡片上的参考标记和不适用原因。 |
| 4:30–5:30 | 回主任务「成本草案」，展开成本依据和工序，查看毛坯。可点「系统预览 · 模拟 → 加载预览」。 | 100 件单价 **€25.47**、总价 **€2,547.00**。毛坯为 `82 × 52 × 13 mm`、每件用 1 件、批量 100 件。模拟预览可对照 PLM 发布版次、ERP 草案和 MES 工时。 |
| 5:30–6:45 | 把「当前角色」切为审批人，从最近任务打开同一条。进「审批与审计」，勾选复核确认，填备注 `核对 B 版、材料与成本依据，批准用于内部预算`。点击「批准当前草案」，再点「生成导出文件」。分别下载 Markdown 和 JSON。 | Markdown 可供人阅读，JSON 保留结构化报价、毛坯和批准数据。打开审计时间线查看谁批准和何时导出。 |
| 6:45–8:15 | 打开 03，确认引用仍是 `PM-INT-001` 且数量更新为 500。切回工程师，打开**原任务**，在「资料与证据 → 工程确认与补充依据」选择「数量」，确认值填 `500`，原因填 `客户澄清 PM-INT-001 clarification 01，批量由 100 改为 500`。点「保存并重新校验」，先查看审批与成本，再回任务总览点「继续处理」。 | 保存时原草案与批准清除。重算为 **€24.51/件、€12,255.00**，毛坯 500 件，任务重新待审批。字段保留原值 100、当前值 500 和修改原因。 |
| 8:15–9:55 | 新建第二个「准备内部报价」任务，上传 04 和 05，选「本地文本识别」，点「继续处理」。展示阻断后，回任务总览的「补充 / 替换图纸」只选 02，点「保存资料」，再点「继续处理」。 | 先出现要求 B、图纸 A 和 `REVISION_CONFLICT`，没有可审批报价。换图后同一任务恢复并出现 €2,547.00 待审批草案。审计中可追溯补件和重新处理。 |
| 9:55–11:10 | 新建「图纸审查」任务，仅上传 02，保存并继续处理。接着新建「查询受控知识」任务，留空关键词并继续处理。 | 审图输出是字段、证据和待复核范围。知识任务输出是受控资料快照。两个任务都不生成报价。 |
| 11:10–12:00 | 回到 M7 报告，展示合成冻结集结果。用一两句话交代试点下一步。 | 报价正例 4/4、异常阻断 8/8。扫描件的 8 个正确视觉字段仍需工程师确认。试点测真实资料适用率、主动工程工时与收件到批准的周期。 |

**数量变更操作。** 03 在独立标签页阅读，用其中的编号和数量填写人工确认。它不作为新 RFQ 上传。这样同一任务保留 01 的原始文档和 100 件原值，修改原因记录在审计里。若现场还有时间，可给 500 件草案再审批一次并下载新版，前后两个文件按各自批准版本归档。

**换图备用入口。** 如果现场已在「资料与证据」页，也可用「补充正确版次图纸」。在共用的「依据 / 修改原因」栏填写例如 `收到已发布 B 版图纸`，选 02 并确认替换，再继续处理。两种换图入口选择其一即可。不要把 A 版字段手填成 B。

## 3. 输出验收清单

| 功能 | 输出与核对项 |
|---|---|
| 抽取与核验 | 原始 RFQ 和图纸、料号与数量等字段、字段证据、PDF 页图、识别方式与问题。在线调用记录随该任务查看。 |
| 受控知识 | 适用的批准目录、工艺模板和有效费率。历史、过期和不适用资料显示各自限制。知识任务保留查询结果快照。 |
| 成本与物料 | 成本明细、工艺、毛坯每件及批量用量、单价及总价。100 件和 500 件各对应自己的价格与批准版本。 |
| 审批与交付 | 授权审批人下载 Markdown 与 JSON。Markdown 适合审阅，JSON 可核对 `quote`、`material_lines`、`approval` 与内部草案标识。审计保留批准、导出、修正与补件动作。 |
| 错版与缺失 | 版次冲突时停止报价，补正确原图后恢复。用 01 + 06 另开任务可演示材料显示未知、计价阻断。 |
| 单图纸与模拟集成 | 单图纸审查仅产生工程检查结果。PLM、ERP、MES 的模拟预览可作为数据映射的演示。 |

## 4. 3 分钟短版与备用

1. **0:00–0:35** 展示 01 和 02，说明模型、程序和审批人的分工。
2. **0:35–1:15** 打开预先用 01 + 02 跑通的任务，展示材料证据和页图，明确是已保存的任务。展示在线记录时只采用实际在线运行的任务。
3. **1:15–2:10** 展示 €2,547.00 和已批准的 Markdown 或 JSON，打开 03，切工程师修改数量，展示旧审批消失与 €12,255.00 待审批结果。
4. **2:10–2:45** 打开预先用 04 + 05 跑出的 A/B 冲突。展示阻断以及可替换的 02；时间足够时现场完成换图。
5. **2:45–3:00** 用 M7 合成集的 4/4 正例和 8/8 阻断收尾。

如果在线结果停在工程复核，先打开对应页图核对字段，再按依据确认或补件。若现场时间有限或在线服务不可用，可在调用结束后用同一组 PDF 切换到本地文本识别继续，或打开已保存的任务查看证据。现场讲明当前模式。内置 `REPLAY` 绑定原始文件哈希，演示该模式时选择原始 DEV-001 内置样例。

需要加演时，用 01 + 06 展示材料缺失，再展示批准资料到位后如何补正确图纸。审批人与工程师的知识查询数量差异可用两条分别创建的任务对照。预先下载的草案可以作为浏览器下载受限时的备用展示。

## 5. 复用与验收

在仓库根目录执行 `python scripts/generate_interview_pdfs.py` 可用项目依赖重建同名材料。六份 PDF 已逐页渲染，并用新建数据库通过工作台所用 API 验证正常报价、变更失效、错版恢复、审图、知识查询与材料缺失。
